# Send/Receive considerations

*User Interface › Menus › Send/Receive*

> [!IMPORTANT]
>
> - Discuss making backup copies *of the repository* if the *shared* repository is on a USB Flash Drive or in a Chorus Hub folder on a networked computer.
>
> If you use Chorus Hub, you could run Chorus Hub on one of the computers on which FLEx or WeSay is used, or on a dedicated computer. In some cases, a dedicated computer could provide an additional level of safety for the repository.
>
> - [Collection of Locale Data](../../Advanced_Tasks/Writing_Systems/Modifying_a_Writing_System/Collection_of_Locale_data.md) describes that SIL may collect writing system data from repositories stored on Lexbox (formerly *Language Depot*) internet server.
>
> - As a general rule, data are included when you use the send/receive feature; Personal settings, such as views, are *not* included. You need to install fonts and keyboards on each computer or device separately.\
>   For more details, see <a href="https://software.sil.org/fieldworks/support/using-sendreceive/" target="_blank" title="https://software.sil.org/fieldworks/support/using-sendreceive/">https://software.sil.org/fieldworks/support/using-sendreceive/</a>.
>
> - Discuss the use of [Backup and Restore](../../User_Interface/Menus/File/Backup_and_Restore/Backup_and_Restore_overview.md). Consider the following:
>
> - - Each repository is a copy of the language project data.
>
> This *may or may not* influence how often local backup copies should be made by each person.
>
> *FLEx will only allow you to restore a backup file if you use a different name.* If someone restores an old backup file, a lot of old unwanted data can be sent to the repository and worse, the potential loss of any new data and changes done since the backup file was made.
>
> 1.  - *Multiple shared repositories* are also possible, and this is a possible way to back up the project.
>
> For example, one could be on the Internet and another one in a Chorus Hub folder or on a USB flash drive. This would require more rigorous coordination, but could help ensure data preservation.
>
> - Discuss and coordinate the use of Bulk Edit, especially bulk *deletions* to minimize merge conflicts.
>
> - - Each should use Send/Receive *before* doing bulk-edit changes (recommended).
>
> - *Discuss and coordinate anytime someone wants to [delete](../../Advanced_Tasks/Writing_Systems/Modifying_a_Writing_System/Delete_a_writing_system.md) or [modify](../../Advanced_Tasks/Writing_Systems/Modifying_a_Writing_System/Modifying_a_writing_system_overview.md) a writing system.*
>
> - *On the* **Send/Receive** *menu, click![](../../assets/images/User_Interface/Menus/Send_Receive/SRGlobe.png)* **About Flex Bridge**. Then click the **Flex Bridge Limitations** hyperlink for more information.

> [!NOTE]
>
> - Whether you *primarily* use the Internet, USB Flash Drive, or Chorus Hub depends on you team's access to a good internet connection, security considerations, and so on. Get [input and opinions](../../Overview/Technical_support.md) from others who have been using Send/Receive.
>
> - If the [spelling status](../Spell_Checking/Spell_checking_overview.md) of words are changed by received data, the [spelling dictionary files](../Spell_Checking/dictionary_files.md) on the local computer are updated.
>
> - [Folder Structure](../../User_Interface/Menus/File/Backup_and_Restore/Folder_Structure.md) discusses folders, their locations and intended use.
